# 提案：優先使用 LINE 原生無障礙，保留便利快捷鍵

您好，感謝您持續改善 LINE 的無障礙使用體驗。

我停用 LINE MR，並將 LINE 與通話、媒體程序中的橋接器副本停用、完整重新啟動後，發現目前 LINE 原生無障礙的表現優於我的預期。實際觀察到原生介面已提供聊天清單、訊息文字、輸入框，以及部分訊息中的時間、已讀與回覆引用資訊。

這不表示原生功能已全面完善，但我想提出另一個開發方向：優先沿用原生無障礙，附加元件集中補上使用者需要的便利功能，對確實不足的部分再考慮橋接器補強。

## 希望保留的功能

1. 保留原本方便的快捷鍵，例如 Alt+C 直接回到聊天清單，以及 Alt+I 跳到訊息輸入框。這類明確由使用者按鍵觸發的定位功能，對日常使用仍很有幫助。
2. 依我目前實測，LINE 原生 Ctrl+1、Ctrl+2 已能切換至好友／聊天列表，但如果已經在對應分頁，再按一次不一定會把焦點帶回列表。因此 Alt+C 這種「不論是否已在聊天分頁，都能直接定位清單」的功能仍有必要。這是目前環境的使用回報，尚未確認其他版本或電腦是否一致。
3. 接聽、拒接與掛斷通話等功能，我還沒有完成原生環境測試。因此目前不建議直接移除這些既有輔助功能，也不宣稱原生已能替代。
4. 回覆、刪除此裝置訊息與收回的快捷鍵，也希望能保留。我附上一個不載入橋接器的小附加元件原始碼，作為直接操作原生介面的參考。

## 附帶的參考實作

原始碼位於 [examples/native-message-actions](../examples/native-message-actions/README.md)。它是一個獨立的實驗元件，提供可在 NVDA 輸入手勢中重新映射的：

- Alt+R：回覆目前訊息。
- Delete：刪除此裝置上的目前訊息。
- Shift+Delete：收回目前訊息。

它不安裝或修復 DLL、不讀取繪圖內容、不接管 Enter/Tab/Shift+Tab，也不自動確認刪除／收回。只有使用者按下對應手勢時才尋找原生訊息選單。Alt+C、Alt+I 的原生定位版本尚未包含在此範例中，仍屬本提案希望保留的功能。

目前使用者已回報收回成功；回覆曾經出現選單已開啟、UIA 動作回傳後仍未真正執行的情況。最新範例補上修飾鍵放開後開選單，以及僅在原回覆按鈕仍確實取得焦點時補送一次 Enter 的處理，但最後這項回覆修正尚未取得使用者驗收。刪除也尚未完成真實訊息的端到端測試。範例附有 13 組離線測試，但不能將它們當成所有原生操作已驗證。

這是一份開發策略提案與參考原始碼，不是要求立即替換現有架構。也希望能先討論「原生無障礙＋使用者觸發的快捷鍵」是否適合專案方向，再逐項確認哪些部分仍需要橋接器。原專案版本與現行功能在這份 PR 中均不修改。
